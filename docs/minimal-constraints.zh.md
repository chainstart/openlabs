# OpenLabs 最小约束架构

OpenLabs 把 Codex 视为每轮科研过程的决策者。控制面不选择科学路线、不规定阶段顺序、不按
中间文件或活动量判定完成，也不因得到一个局部结果就终止尚未达到目标的任务。

仓库只保留五类外部硬门禁：

1. **时间与资源**：任务 wall time、campaign 总 Agent-time，以及仓库聚合 CPU、内存、swap
   和进程数护栏。
2. **事务与恢复**：每次 attempt 在私有副本中工作；有效 `completed` 和 `needs_replan`
   原子晋级，失败、取消、损坏或门禁不通过的 attempt 隔离。
3. **证据与可复现性**：声明的本地证据必须存在、哈希绑定；可执行证据必须声明输入闭包并
   重放通过；领域协议只验证状态与证据语义。
4. **认知独立性**：作者不能审核自己的核心结论；独立复现、reviewer 和跨角色 handoff 使用
   新会话。普通同角色研究可以恢复原 session。
5. **成果与写作晋级**：问题解决、局部定理/计算成果和稿件就绪分别记录。论文候选必须通过
   领域证据、当前新颖性、写作规范、双提供方独立审稿和 CAS 大类一区视角；内部就绪仅授权
   发布已准备且哈希绑定的论文支撑材料，不授权投稿、署名变更、付费、期刊事件或论文发表事实。

研究内部的分解、工具、模型、推导顺序、实验设计、失败路线、检查点频率和阶段目标由 Codex
按证据与剩余预算自行决定。`needs_replan` 是带可执行后继动作的有效恢复检查点，不是完成；
中间 lemma、baseline、null result、literature update 或某条路线被否证也都不是自动停止条件。

仓库不再支持 `continuation: one_shot`、Skill 自带的 phase authority policy，或
`checkpoint_policy`/`continue_across_protocol_phases` 这类重复控制开关。项目只可选择连续研究
或“有新结果时独立审查”；会话策略只保留默认恢复模式和必须 fresh 的认知边界。
