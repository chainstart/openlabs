# 统一评审流程设计（编辑初审 + 审稿人评审）

状态：2026-10-06 确认并实现，之后按用户决定调整：2026-10-12 收敛形式核验范围；2026-11-07
恢复跨模型双审稿人并增加面向编辑的重写环节；2026-11 评审收敛（只有科学实质阻断、形式检查
移到交付出口、轮次上限改为 4）。编辑、审稿人、各自模型和轮次上限只以数据仓库
`registry/settings.yaml#review` 为准，本文不重复具体模型名和数字。操作说明见
[openlabs-paper-review](../skills/openlabs-paper-review/SKILL.md)。

## 1. 目标

评审只做一件事：在投稿前尽量逼真地模拟**目标期刊**的编辑和审稿人，尤其是尽量避免桌拒。
内部评审的结论必须能和真实期刊的决定对得上；对不上就是流程的缺陷，而不是论文的运气。

不变的原则：审阅者在全新进程中工作，看不到作者会话和以往评分；确定性代码只做校验和合并，
不产生判断；科学阻塞不能被投票或分数抹掉；评审结论不授权投稿、发布或任何外部写入。

## 2. 为什么这样设计（2026-10-06 分析）

1. **路径过多。** 当时有全文评审、增量评审、元数据复用、三种 closeout、editorial follow-up
   和单独的编辑筛查共 8 条路径，多为单次事件临时增加。现在只剩 `review unified-run`。
2. **标尺与目标脱节。** 对照顶刊打分再给泛化的“1 区”意见，没有区分力；实际投稿 8 篇 12 次
   全部桌拒。现在按目标期刊本身的送审标准判断。
3. **顺序颠倒。** 真实流程是编辑先决定是否送审，所以编辑初审放在审稿之前。
4. **迭代过拟合。** 单篇最多 22、31 轮，“结论过强”被一句免责声明打发。现在禁止这种回应，
   文字意见不再进入下轮追踪，轮次也收紧。
5. **作者与审稿同系。** 盲评实验中两家模型的评委各有 4/5 偏向自家文字，所以至少一名审稿人
   的模型必须不同于撰稿模型（`review.cross_model.required`）。

## 3. 流程

```
投前检查 ──► 编辑初审 ──► 审稿人（2 人，盲审，并行） ──► 书目与核心数学核验 ──► 合并与决定信
                │ 桌拒/投前需改                                                  │
                └──► 返修 / 补证据 / 方向性决定 ◄────────────────────────────────┘
```

**投前检查（确定性）。** 只拦截让评审失去意义的问题：稿件无法编译、登记或证据哈希绑定损坏、
目标期刊违反选刊政策、声明的来源指向不存在的参考文献键、该目标还没跑过一次面向编辑重写。
风格、AI 声明、摘要格式、未使用源文件、支撑记录等形式问题记为 `preparation_advisories`，
在交付出口（handoff、`zenodo release`）强制执行，不消耗科学轮次。内部术语黑名单只报告所在
句子，由人判断。重写环节每个目标跑一次，结论只作建议。

**编辑初审。** 全新进程扮演目标期刊的处理编辑，读标题、摘要、引言、主要结果陈述、参考文献、
最接近的已有工作和本稿全部真实拒信，给出两句话复述的贡献、最强桌拒理由（`scope |
significance | readership | novelty_unclear | presentation | incremental`）和决定
`send_to_review | desk_reject | revise_before_submission`。范围或读者不符返回
`retarget_required`；意义不足或增量返回 `direction_decision`（附 `direction_context`），由
编排器做方向性决定，而不是继续打磨文字。

**审稿人。** 各自全新进程，读完整冻结稿、补充材料和支撑包，给出期刊词汇的建议
（`accept | minor_revision | major_revision | reject`）、`scientific_blockers` 和带类型的
`required_changes`（`evidence | claim_narrowing | text`，后者另标 `main_claim`）。凡以免责
段落回应“结论过强”，视为未解决。

**书目与核心数学核验。** 科学结论允许继续时才运行，由 `review.roles.formal_verifier`（未配置
时为编辑模型）执行：每条参考文献对照权威元数据，定理、证明、展示公式和行内推导按数学核对。
真实错误、必要证明缺口和错误或无法识别的文献身份阻断；仅因网络或访问失败取不到记录的文献
记为 `unverifiable_source_access`，留待人工或其他环境核对。细节见
[formal-checks.md](../skills/openlabs-paper-review/references/formal-checks.md)。

**合并。** 只有科学实质阻断：`ready` 需要编辑送审、无科学阻塞、无 `evidence` 修改、无主结论
收窄、无未解决的上轮科学/证据项，且建议为 `accept` 或 `minor_revision`。审稿人意见分歧时取
较有利者，除非较严者有上述实质项支撑。`text` 意见为建议，写入决定信和 `advisory_changes`，
不进入下轮追踪。双审稿人都 `reject` 时返回 `direction_decision`。连续两轮意义与新颖性均分
不升且未要求补证据时标记 `stalled`，提示编排器停止打磨。分数只记录供校准；升档目标另需每位
审稿人达到升档分数线。

**通过后的差异复核。** 已 ready 的稿件之后只改文字或图件时（题名、摘要、引言、定理陈述、
表格、结论类章节和全文数字均未变，且改动行数很少），沿用原评审结论、重跑形式核验，不消耗
轮次；否则进行完整评审。

**轮次。** 每个目标期刊的科学轮次上限为 `review.max_rounds_per_target`，纯技术失败不计。
用尽后论文为 `blocked`，由编排器做方向性决定（换刊、补研究或冻结）。

## 4. 记录

每次运行写入 `reviews/unified/<paper_id>/<run_id>/`：`decision.json`
（`openlabs.review.decision.v1`）、各角色提示、输出和带实际模型的回执。`writing_release`
绑定决定记录哈希以及稿件、登记和支撑材料指纹；应用决定与交接时重查，策略改变后旧结论不能
沿用。旧格式（`ara.paper_writing.review.v2`、`review.single.v1`、各类 closeout 证书）保持
可读，但不能再使论文进入 `ready`。旧面板下启动的评审绑定 `review.previous_panels` 中的对应
配置。

## 5. 校准

`review calibration` 从管理网站拉取真实投稿事件，与当时的编辑初审和合并结论对照。若内部
`send_to_review` 的论文仍频繁被桌拒，就收紧编辑初审标尺。校准只读，不修改历史记录。

## 6. 历史拒信（2026-10-09）

编辑初审必须逐封读取原拒信（原文与源 SHA-256），判为已实质克服 `resolved`，或以目标期刊的
具体范围、读者和贡献门槛说明与原拒信不矛盾 `compatible`。缺原文、漏评、未克服或矛盾时不能
进入审稿。仅换刊、改措辞或作者自称已修复不满足条件；拒信缺失须恢复原信，不得由摘要生成。
逐篇授权的缺信政策见 [REJECTION_HISTORY_POLICY.zh.md](REJECTION_HISTORY_POLICY.zh.md)。

## 7. 真实期刊返修上下文（2026-10-17）

正在返修的稿件可用 registry 的 `journal_revision_context` 绑定原始决定信、外审报告及可选的
原始投稿文本。期刊和稿号必须与当前 `submission_followup` 一致；每个原始文件按路径、大小及
SHA-256 核验，不能用作者摘要替代原件，也不能引入 `reviews/` 下的内部判断。这些原件与作者
逐条回复同时送入编辑和审稿输入；返修邀请不登记成拒稿，不代表录用，也不豁免任何标准。
上下文在应用决定和交接时再次核验，改变或缺失会阻止沿用旧判断。
